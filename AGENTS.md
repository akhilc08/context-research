# Repository guide

This repository studies context management for long-running coding agents. The current focus is context compaction, what it loses, and how to measure or repair that loss.

## Start here

1. Inspect `git status --short --branch` and `git log -5 --oneline` before editing.
2. Read `README.md` and the documents relevant to the task.
3. Preserve the meaning, evidence state, metrics, citations, and uncertainty in research documents unless the task explicitly changes them.
4. Make the smallest complete change, run the checks that can prove it, and inspect the final diff.

## Shared skills

- Use `plain-docs` when drafting or revising human-facing Markdown.
- Use `commit-conventions` when naming a commit.

Work directly on `main` unless the user asks for another workflow. Treat the repository guidance and commit conventions as the pattern for new work. Existing history may predate them.
