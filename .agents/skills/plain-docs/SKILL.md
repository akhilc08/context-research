# Plain docs

1. Write for a technically curious person, not an academic audience. Use ordinary words and natural phrasing without becoming casual or imprecise.
2. Preserve the facts, uncertainty, evidence state, metrics, citations, and intended meaning. Do not turn an estimate into a measured result, a lead into a verified source, or a proposal into a decision.
3. Give each sentence one main point. Split cramped sentences while keeping the explanation complete.
4. Name the actor, method, or source when it matters. Explain necessary technical terms on first use.
5. Use headings to expose the argument. Use lists and tables only when they make comparison or scanning easier.
6. Remove repeated explanations and empty emphasis. Keep one useful example instead of several weak ones.
7. Use periods, commas, or parentheses instead of em dashes and en dashes in prose. Write ranges with `to`.
8. Read the result as a newcomer. Confirm that each clause adds needed information and that causes, contrasts, caveats, and exceptions remain clear.
